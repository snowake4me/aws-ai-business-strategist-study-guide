## Theme 1 — The stem stated the eliminating fact; the pick won on register (4 of 6: Q9, Q10, Q13, Q18)

In four misses the stem contained a fact that, read literally, kills the chosen
option. The option won anyway because it *sounded* like the exam's preferred register.

| Q | Fact in the stem that was ignored | What the pick sounded like |
|---|---|---|
| 9 | Stated daily volume and a weekly peak; process already in production | Prudent ("short pilot") |
| 10 | "Workforce **efficiency**" as a required KPI dimension | People-centric ("alerts reviewed by technicians") |
| 13 | Three explicit if-then rules with thresholds and an exception | Strategic, AI-forward ("learn from history") |
| 18 | "Updates the model every two months" | Used the stem's words ("recent sales data") |

This is **discipline, not knowledge.** In every case the correct concept was known.

**And now the mechanism is visible.** TD's per-question timer shows 0:00 for items
skipped on the first pass and answered at the end. Five questions on the form were
skipped that way. **Four were missed**, and all four are this theme (Q9, Q10, Q13,
Q18). The one survivor (D4 #8) was a maturity-model question with no register bait
in the options. The two other misses, answered in place with 1:26 and 1:41 on the
clock, are the two knowledge themes. So the register-over-facts failure is not a
general reading habit. It is what happens **on the return visit to a deferred
question**: come back cold, skim the stem instead of re-reading it, pick the option
that sounds right.

| Handling | Count | Correct |
|---|---|---|
| Skipped first pass, answered at end | 5 | 1 (20%) |
| Flagged, answered in place | 10 | 8 (80%) |
| Neither | 50 | 50 (100%) |

Hesitating and committing worked. Deferring did not.

**Drill, two parts.**

1. **Do not skip.** Answer provisionally, flag, move on. Skipping drops the stem from
   memory; a provisional answer keeps the analysis attached to the question.
2. On any return visit, **re-read the stem from the top** before looking at the
   options, then name the fact in the stem that eliminates each rejected option. If
   no fact can be named, the choice is being made on tone. On Select-TWO, do it for
   each *accepted* element as well.

**Fix:** flashcards for the four individual rules (below), and this drill as the first
entry in `decision-patterns/exam-traps.md`.

## Theme 2 — The rules / RAG / agent boundary is not held precisely (Q13, Q65)

Mirror-image misses on the same axis. Q13 picked AI when the stem had spelled out the
rules. Q65 picked rules when the stem said the next step depends on the result of the
previous one. Missing both directions means the boundary is fuzzy rather than biased.

The exam guide lists this axis in three separate skills (1.2.1 rules vs AI, 1.2.2
agents vs other AI, 2.1.4 when AI is not appropriate), so it is worth more than two
questions' weight on the real form.

**The rule, both directions:**

- Stem *states* the decision logic (thresholds, fixed outcomes, named exceptions) →
  **rules.** Volume and history are enablers, not needs.
- Stem says *choose*, *depending on the case*, *based on the result of a previous
  action*, and lists actions on external systems → **agent with tools.**
- Stem says *answer*, *summarize*, *explain*, grounded in documents, no external state
  changes → **RAG assistant**, which is not an agent.

**Fix:** the capability-ladder cheat card in `decision-patterns/` and TD Section-Based
mode on Domain 1 to get more reps on this axis specifically.

## Theme 3 — One real misconception: "more context means fewer missing details" (Q51)

The only miss reached by reasoning rather than by skimming. The belief that including
everything would prevent details going missing is backwards once the input exceeds
the context window; the model is already dropping content, and adding more makes it
drop more. The stem's *works small, fails large* pattern is the diagnostic.

**Resolved (partially):** Q51 shows in TD's *Skipped + Marked for Review* filter, so
it was not a blind miss, with the caveat that the filter cannot separate flagged from
skipped. It stays a normal knowledge item, not the top of the table.

**Fix:** the symptom-to-lever table (context window · max output tokens · temperature
and top-p · RAG · fine-tuning) as a `decision-patterns/genai-levers.md` cheat card.
Every 1.3.x skill is a variation of "which lever for which symptom."
